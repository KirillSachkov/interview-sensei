# Хранилище: PGlite в одном процессе-владельце

Версия 1 хранит данные в PGlite — PostgreSQL, встроенном в Node-процесс. Схема описана в Drizzle на диалекте `pg`.
Мы выбрали PGlite, потому что он даёт SQL PostgreSQL, русский полнотекстовый поиск и pgvector без установки сервера. Пользователь запускает приложение одной командой `npx interview-sensei`.
Каталог базы открывает только локальный сервер приложения. UI, MCP и ACP-мост обращаются к данным через этот сервер.

## Considered Options

- PostgreSQL-сервер через Docker или локальную установку: надёжнее и без ограничения на процессы, но поднимает порог установки.
- SQLite с FTS5: несколько процессов в режиме WAL, но нет русского стемминга, а схему для версии 2 пришлось бы переносить.
- Markdown и YAML как источник истины: наглядно, но неудобно для журнала попыток и одновременной записи.

## Consequences

- Второй процесс не может открыть ту же базу: PGlite не блокирует каталог, и одновременное открытие ломает данные.
- PGlite работает без fsync. Сервер делает регулярный dump.
- Сырые файлы источников лежат в каталоге данных под хэшем. База хранит их метаданные и извлечённый текст.
- Векторного конвейера нет. Агент ищет через полнотекстовый поиск PostgreSQL; pgvector остаётся точкой расширения.
- Версия 2 может взять схему и запросы и сменить драйвер на PostgreSQL-сервер.

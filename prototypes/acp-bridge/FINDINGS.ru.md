# Прототип ACP-моста: результаты

Прототип одноразовый, тикет #4. Запуск: `pnpm install`, затем `node server.mjs --agent claude|codex|opencode --port 4710 [--mode default]`.
Чат открывается на `http://127.0.0.1:4710/`. Скрипт `drive.mjs` заменяет вкладку браузера в автоматических прогонах.

## Ответ

Схема работает со всеми тремя агентами. Fastify-сервер запускает агента через stdio и передаёт ему наш MCP-сервер в `session/new` как `{type:"http"}`.
Каждый агент вызвал `get_session_brief` и `present_question`, а сервер отправил карточку вопроса в браузер по WebSocket.
`session/fork` вернул новую сессию у всех трёх агентов. Основной риск лежит не в транспорте, а в разрешениях и в окружении пользователя.

## Агенты

| Claude | `claude-agent-acp` 0.101.0 | 0,2–0,8 с | 3,6 с холодный, 0,35 с повторный | оба дошли | 14,4 с | 14,3 с | ok, 0,3 с |
| Codex | `codex-acp` 2.5.0 | 3,0 с | 3,6 с | оба дошли | 27,0 с | 5,7 с | ok, 0,1 с |

Ни один агент не потребовал входа: все использовали существующую авторизацию владельца.
Codex объявляет `authMethods` `api-key` и `chat-gpt`, OpenCode объявляет `opencode-login`, Claude объявляет пустой список.

Адаптеры несут собственного агента. `claude-agent-acp` ходит в MCP как `claude-code/2.1.318`, хотя в системе установлен `claude` 2.1.316.
`codex-acp` использует `codex-mcp-client/0.165.0`, хотя установлен `codex-cli` 0.167.0. Версию агента задаёт адаптер, а не CLI пользователя.

## MCP

Stateless streamable HTTP из `@modelcontextprotocol/sdk` 1.32.2 подключился к Fastify через `reply.hijack()` и `req.raw`.
Все агенты выполнили `initialize` и `tools/list` во время `session/new`, то есть до первого prompt. Claude и OpenCode также открыли GET-поток; ответ 405 им не помешал.
Время от `tools/call` до события в браузере не превышало 10 мс.
Claude нашёл наши инструменты через `ToolSearch` (отложенная загрузка) и потратил на это лишний шаг около 2 с.
Codex заново подключает MCP после `session/fork`.

## Разрешения

Поведение разрешений сильно различается между агентами.

- **Claude.** Сессия стартовала в `bypassPermissions`, потому что адаптер берёт режим из настроек пользователя. После `session/set_mode default` агент запросил разрешение на каждый вызов нашего MCP. В запросе есть `_meta.claudeCode.mcpServer.name`. Команду `date` Claude выполнил без запроса.
- **Codex.** Режим по умолчанию `agent` (Auto review) не отправляет `session/request_permission`. Вместо запроса модель «Guardian Review» оценивает вызов и добавляет около 7 с к каждому вызову MCP. В режиме `read-only` запрос пришёл с `_meta.is_mcp_tool_approval: true`, но без `title` и без имени инструмента.
- **OpenCode.** Агент не отправил ни одного запроса разрешения: ни для MCP, ни для `bash`. Режимов нет.

Ошибка прототипа показала важное правило. Сначала сервер искал имя нашего сервера регуляркой по всему `toolCall`.
Регулярка разрешила `touch x.txt`, потому что путь `cwd` содержит `interview-sensei`. Запросы Codex для MCP она, наоборот, пропустила.
Исправленный код связывает запрос с ранее полученным `tool_call` по `toolCallId` и проверяет структурные поля. Исправление не перепроверено на Codex, чтобы не тратить подписку.

## Fork

`session/fork` вернул новый `sessionId` у всех агентов. OpenCode при fork повторяет историю как `session/update` для новой сессии.
Prompt в fork-сессии OpenCode ответил по контексту исходной сессии за 1,4 с. События основной сессии в fork не попали.
Claude и Codex prompt в fork не получали; история при fork у них не повторялась.

## SDK

`@agentclientprotocol/sdk` 2.4.0 не содержит `ClientSideConnection`. Новый API выглядит так: `client().onRequest(...).onNotification(...).connectWith(stream, ctx => ...)`.
Обработчик получает контекст, а параметры лежат в `ctx.params`. Первая версия прототипа передавала контекст как параметры.
Поэтому Claude получил `Tool permission request failed: Internal error` и сообщил о сбое инструментов. Это ушло на один prompt.

## `@acp-components/core` 0.1.0

Вывод: как готовое соединение пакет нам не подходит. Как хранилище состояния он подходит только частично.

- `AcpClient` сам владеет ACP-соединением: он выполняет `initialize`, `newSession` и `prompt`. Тогда сервер становится прозрачным прокси, а MCP и разрешения пришлось бы перехватывать в потоке JSON-RPC.
- Пакет зависит от SDK `^0.22.1` с `ClientSideConnection`. Рядом с 2.4.0 получаются две версии SDK.
- Функция, которая переводит `session/update` в состояние, внутренняя и не экспортируется. `sessionStore` экспортирован; `acp-components-check.mjs` наполнил его ретранслированными событиями через действия хранилища.
- Без `messageId` каждый фрагмент текста становится отдельным сообщением. В `AcpClient` нет `fork`.

Рекомендация: написать свой редьюсер `session/update` примерно на 60 строк. Его можно скопировать из этого пакета под MIT.

## Окружение пользователя

Все три агента загрузили окружение владельца. Claude прочитал глобальный `AGENTS.md`, user skills и slash-команды. Обычно агент отвечал по-русски, OpenCode ответил по-английски.
OpenCode показал skills репозитория, а Codex — свои. Влияние на контекст описано в ветке `research/acp-context-levers`.

## Проблемы

1. Для разрешений нет общей модели. Режим по умолчанию у Claude и Codex зависит от настроек пользователя, а OpenCode не спрашивает вообще.
2. Codex в режиме `agent` добавляет около 7 с к каждому вызову MCP.
3. У Claude весь текст пришёл в конце хода. Чат 14 с показывает только вызовы инструментов.
4. Агенты не прислали ни одного `plan` в коротких prompt.

## Рекомендации для настоящего дизайна

1. Сервер владеет ACP-соединением, а браузер получает уже обработанные события. Схема подтверждена.
2. Передавать MCP как `type: "http"`: его поддерживают все три агента, а `sse` у Codex нет.
3. Узнавать наш инструмент по `toolCallId` и структурным полям каждого адаптера. Регулярку по JSON не использовать.
4. После `session/new` явно задавать режим: `default` для Claude, `read-only` или `workspace-write` для Codex. Для OpenCode ограничения задать отдельно, например через его конфигурацию.
5. В UI показывать события `tool_call` сразу, чтобы долгий ход не выглядел зависшим.
6. Для Side thread использовать `session/fork`. Перед этим проверить prompt в fork-сессиях Claude и Codex.
7. Не использовать `AcpClient` из `@acp-components/core`. Взять за образец его хранилище.

# Проверка тезисов и ручная калибровка Grade

Агент (Codex): исследование по [#101](https://github.com/KirillSachkov/interview-sensei/issues/101), 2026-11-10.
Продолжает [исследование пайплайна](pipeline-evaluation.ru.md).

## Что проверяем

Ссылка на подходящую документацию ещё не подтверждает каждый тезис ответа.
Для ответа «из интернета» агент должен найти опору для каждого фактического утверждения
в пунктах и образце, сохранив API, runtime, версию, условия и исключения.
В этом запуске отдельно проверяем две ошибки из #66 про `abort(reason)` и `ABORT_ERR`.

Для Grade фиксируем [входные данные](reference-calibration/fixture.json) до запуска агентов.
Вопрос, три опорных пункта, образец, уровень middle, критерии секции topics и три ответа
кандидата одинаковы у всех агентов. Сопоставление идёт по `id`, без поиска слов в формулировке.
Техническую правильность проверяем по первоисточнику и локальному опыту отдельно от согласия моделей.

Обязательны передача `signal`, вызов `abort` и различение причины по умолчанию
и переданного `Error`: вопрос явно спрашивает обработку причины.
Практический контекст дан HTTP-запросом и обработчиком `catch`.
`AbortSignal.timeout`, `AbortSignal.any`, повторная отмена и управление слушателями
для этого вопроса необязательны. Их отсутствие не снижает Grade 3.
Заранее ожидаем 3 для `complete`, 0 для `wrong`, 2 для `gap`.
В `gap` описан механизм, но обработка только `AbortError` пропускает пользовательский `Error`.
Это ручной диагностический набор, а не автоматическая оценка в приложении или CI.

## Независимая проверка техники

[Node.js, abort(reason)](https://nodejs.org/api/globals.html#abortcontrollerabortreason)
задаёт произвольный reason в `signal.reason`.
[Fetch Standard, fetch method](https://fetch.spec.whatwg.org/#dom-global-fetch)
передаёт причину сигнала в алгоритм отмены, а
[abort fetch](https://fetch.spec.whatwg.org/#abort-fetch) отклоняет Promise с этой причиной.
Это подтверждает механизм и передачу Error, а не универсальный строковый код ошибки.

В [локальном опыте на Node 24.21.0](reference-calibration/node-fetch.json)
заранее отменённый сигнал без reason дал `AbortError`, `code: 20`.
С переданным `Error` отклонение сохранило тот же объект, без `code`.
Запрос использовал заранее отменённый сигнал, поэтому не выходил в сеть.
Это наблюдение для указанной версии Node; оно не задаёт поведение всех API отмены.

Для повторения локального опыта:

```js
for (const custom of [false, true]) {
  const controller = new AbortController();
  const reason = new Error("owner cancellation");
  custom ? controller.abort(reason) : controller.abort();
  try {
    await fetch("http://127.0.0.1:1", { signal: controller.signal });
  } catch (error) {
    console.log(custom, error.name, error.code, error === controller.signal.reason);
  }
}
```

## Протокол живого прогона

Владелец разрешил расход подписки в текущем поручении.
Каждый агент запускается через ACP и `agentRuntimeModule` приложения с текущим скиллом,
в отдельной свежей сессии. Данные и копии скиллов находятся во временном каталоге приложения.
В систему ничего не устанавливается. Claude Code использует существующий вход владельца
по принятому исключению #24.

Точные [prompt и дополнение к роли](reference-calibration/protocol.json) сохранены отдельно.
Для оценки к `gradingPromptPrefix` добавляется JSON из `fixture.json` через `JSON.stringify`.
В диагностике оценки агент получает весь фиксированный набор одним сообщением.
Дополнение к роли заменяет обычную последовательность мока ответом JSON для ручного сравнения;
Follow-up не задаётся. В диагностике источников включён веб-доступ и переданы вопрос
и два сомнительных утверждения. Агент должен прочитать первоисточники, предложить пункты
и образец, указать, где подтверждён каждый тезис, и перечислить исключённые утверждения.
Сопоставление тезисов с источниками запрошено для наблюдаемости опыта; новых полей
в `save_reference_answer` не добавлено.

Адрес MCP в этих сессиях заведомо не обслуживается; предупреждение о недоступных
инструментах ожидаемо. Проверяем применение скилла и веб-инструменты агента,
а не сохранение ответа или `record_attempt` через MCP и не интерфейс приложения.
Сырые ACP-журналы с локальными настройками не публикуются.

## Результаты

[Оценки и обоснования](reference-calibration/grades.json) сохранены целиком.

| Ответ | Ожидание | Claude Code | Codex | OpenCode |
| --- | --- | --- | --- | --- |
| `complete` | 3 | 3 | 3 | 3 |
| `wrong` | 0 | 0 | 0 | 0 |
| `gap` | 2 | 2 | 2 | 2 |

Это совпадение в одном запуске на одном вопросе, а не статистическая калибровка.
У `gap` Claude Code засчитал пункт 2 по упоминанию AbortError, Codex и OpenCode не засчитали:
они потребовали точнее назвать DOMException. Итоговая оценка совпала; покрытие и объяснения различаются.
Указание типа DOMException само по себе не должно становиться отдельным основанием снижения
за этот ответ: существенный пробел здесь состоит в обработке пользовательского Error.

[Ответы проверки источников](reference-calibration/sources.json) содержат предложенные пункты,
образцы, ссылки, утверждения с адресами источников и исключённые тезисы.
Дословные выписки из страниц и служебные сообщения ACP в публикацию не включены.
Claude Code и Codex отвергли оба исходных ошибочных обобщения.
Codex ограничил пользовательскую причину примером Error и проверкой идентичности объекта,
что согласуется с независимым локальным опытом и алгоритмом Fetch.
Ссылки на ветку main исходников Node в ответе Codex не фиксируют версию;
версионное подтверждение в этом отчёте даёт отдельный опыт на Node 24.21.0.

Первый ответ Claude Code добавил в ключевые пункты историю версий fetch.
После этого в скилл добавлен заключительный проход удаления необязательных деталей.
Повтор с тем же диагностическим prompt на свежей сессии снова добавил историю версий
и `throwIfAborted`; в `sources.json` сохранён этот последний ответ.
Следовательно, новая инструкция не гарантирует удаления всех лишних деталей.
Кроме того, фраза образца Claude Code «все остальные ошибки считаю сетевыми» слишком широка:
отдельная ошибка может иметь иную причину. Такой образец требует ручной правки перед использованием.
Согласие агентов по двум исходным ошибкам не подтверждает каждое новое утверждение.

OpenCode в проверке источников не выдал итогового ответа за 240 секунд;
диагностика отменила ход. В журнале есть вызовы webfetch, в том числе неуспешные,
но их нельзя считать завершённым проверенным ответом. Оценка трёх фиксированных ответов
у OpenCode завершилась отдельно. Повтор веб-проверки здесь не проводился.

Скилл интервью во всех трёх прогонах одинаков.
Claude Code впервые проверял источники до заключительного правила удаления деталей;
повтор Claude Code и веб-проверка Codex использовали окончательный текст.
OpenCode получил окончательный текст, но завершённого результата нет.
Отдельный живой прогон Inbox с новым правилом в этой работе не проводился.

## Как повторить вручную

1. Зафиксировать вопрос, опорные пункты, уровень, критерии секции и тексты ответов до запуска.
   Отдельно записать обязательные идеи и необязательные детали.
2. В свежих сессиях трёх агентов передать побайтно одинаковый набор с текущим скиллом оценки.
   Записать Grade, покрытие пунктов, пробелы и обоснование для каждого `id`.
3. Для спорного факта прочитать первоисточник с нужным API и условиями;
   при возможности отдельно воспроизвести поведение. Согласие моделей доказательством не считать.
4. Сравнить каждую оценку с заранее записанным ожиданием. Снижение за необязательную деталь
   считать расхождением; уточнить источник или формулировку и повторить на свежих сессиях.

## Ограничения

Один вопрос и один запуск на агента не дают статистических выводов об устойчивости.
Ручной диагностический prompt называет спорные тезисы: это направленная проверка,
а не измерение частоты самостоятельных ошибок в наполнении.
Проверки проекта с фейковым агентом проверяют исполнение приложения, но не качество суждений LLM.
Автоматический эталонный оценщик, новые поля хранения и новая шкала Grade не добавлены.

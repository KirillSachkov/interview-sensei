# Форматы технических собеседований по направлениям

Исследование к issue #12. Дата: 2026-11-08.
Вопрос: какие форматы Interview format поддержать в версии 1, где агент ведёт текстовое Mock interview.

Надёжность источников разная. Яндекс, Авито, Ozon Tech, Anthropic и Tech Interview Handbook описывают свой процесс сами. Про AI engineer и Stripe есть только гайды и отчёты кандидатов. Поэтому длительности в документе ориентировочные.

## Таблица «формат × направление»

Обозначения: ●● — почти всегда, ● — часто, ○ — иногда, — — редко.
Последний столбец показывает, работает ли формат текстом с LLM-интервьюером.

| Формат | Go backend | AI/LLM engineer | Frontend | Текстом с LLM |
|---|---|---|---|---|
| Вопросы по темам подряд | ●● (runtime, конкурентность, БД, сети) | ● (RAG, evals, промпты) | ●● (JS, браузер, CSS) | Да, лучше всего |
| Разговор по резюме и опыту | ●● | ●● (разбор проекта) | ●● | Да, нужны резюме и вакансия |
| Одна тема вглубь | ● | ●● | ● | Да |
| System design | ●● с middle+ | ● | ● (frontend system design) | Частично: нет доски |
| LLM/ML system design | — | ●● | — | Частично |
| Логические задачи | ○ | ○ | ○ | Да, но слабый сигнал |
| Live coding и алгоритмы | ●● | ● | ●● (JS- и UI-задачи) | Частично: код без запуска |
| Разбор take-home | ○ | ●● | ○ | Да, если есть репозиторий |
| Behavioral | ● | ● | ● | Да |

Другие направления кратко. Mobile повторяет frontend: язык, платформа, system design клиента. ML engineer в Яндексе проходит ML-теорию, алгоритмы и «ML Special» — разбор одной области вглубь [1]. DevOps и SRE часто получают troubleshooting-кейс. Tech lead в Авито добавляет секцию управленческого опыта и разбор кейса [5].

## Детали по форматам

### 1. Вопросы по темам подряд

Структура: 10–20 коротких вопросов по списку тем, иногда с одним уточнением. Длится 20–40 минут, часто внутри технического скрининга. Пример: вопросы Go о модели G-M-P, закрытых каналах, гонках данных.
Сигналы: точность определений, знание граничных случаев, умение объяснить «почему».
Входные данные: роль, уровень, список тем.
Текстом работает хорошо: ответ легко оценить по эталону, часть вопросов подходит для quiz.
Сложно воспроизвести: скорость устного ответа и уверенность.

### 2. Разговор по резюме и опыту

Структура: кандидат рассказывает о последнем проекте, интервьюер копает в решения, роль кандидата и метрики. Длится 30–60 минут. Ozon даёт этот блок вместе с технической частью [7]. Google называет его частью «role-related knowledge» [9].
Сигналы: личный вклад («я», а не «мы»), обоснование компромиссов, знание цифр, осознание ошибок.
Входные данные: резюме обязательно, вакансия желательна.
Текстом работает: агент генерирует вопросы по резюме.
Сложно: агент не может проверить правдивость ответа.

### 3. Одна тема вглубь

Структура: интервьюер берёт тему и спускается на 4–6 уровней, пока кандидат не дойдёт до предела знаний. Пример: от «что такое map в Go» до эвакуации бакетов и конкурентного доступа. «ML Special» в Яндексе — такая секция [1].
Сигналы: глубина, на которой ответ ломается, и честность на границе знаний.
Входные данные: тема и уровень.
Текстом работает хорошо, но правило «до двух Follow-up на вопрос» мешает. Нужна цепочка связанных Question.
Сложно: выбрать глубину без живой реакции кандидата.

### 4. System design

Структура Авито [4]: требования 5–10 минут, высокоуровневая схема около 20 минут, погружение около 30 минут. Всего около 60 минут. GreatFrontEnd для frontend описывает рамку RADIO: requirements, architecture, data model, interface, optimizations [10].
Сигналы: кандидат сам собирает требования, обосновывает выбор, видит долгосрочные риски, рассматривает альтернативы, рассуждает вслух [4].
Входные данные: уровень; задача может зависеть от команды в вакансии.
Текстом работает частично: схему можно описать списком компонентов или Mermaid.
Сложно: рисование, свободная навигация по схеме, оценка без единого правильного ответа.

### 5. LLM/ML system design

Структура: спроектировать RAG-пайплайн или агента с инструментами. Обсуждают поток данных, поиск, evals, отказы, стоимость, latency и безопасность [11].
Сигналы: выбор chunking и top-k с обоснованием, метрики recall@k и MRR. Кандидат калибрует LLM-as-judge по ручной разметке, а не верит ему без проверки. Он ставит лимиты на вызовы инструментов и называет числа бюджета latency [11].
Входные данные: роль и стек вакансии.
Текстом работает частично, как обычный system design. Область быстро меняется, поэтому эталонные ответы устаревают.

### 6. Логические задачи

Структура: головоломка на 5–15 минут. Крупные компании от них почти отказались. Google оценивает «general cognitive ability» на открытых задачах из работы, а не на головоломках [9].
Сигналы: ход рассуждения, а не ответ.
Текстом работает, но ценность для подготовки низкая. Рекомендую не делать отдельный формат.

### 7. Live coding и алгоритмы

Структура: в Яндексе две алгоритмические задачи за час, код пишут в онлайн-редакторе [1]. Ozon Tech даёт практическую задачу в IDE кандидата и просит запустить тесты [6]. Stripe, по отчётам кандидатов, проводит секции Bug Squash и Integration по 45–60 минут в незнакомом коде [12]. Frontend добавляет JS-функции (debounce, Promise.all) и UI-компоненты [10].
Сигналы Tech Interview Handbook [3]: коммуникация, решение задачи и сложность, техническая компетентность и тесты на граничные случаи.
Текстом работает частично: агент оценивает код и объяснение, но не процесс набора. Нужен запуск тестов, а это уже кодовая проверка.
Сложно: наблюдать процесс, подсказывать по ходу, проверять корректность без запуска.

### 8. Разбор take-home

Структура: кандидат делает задание за 4–6 часов, потом 45–60 минут защищает решение. Для AI engineer типично: RAG-система и маленький eval-набор с метриками [11]. Anthropic запрещает AI в take-home, если явно не разрешил иное (обновлено 2025-07-10) [13].
Сигналы: архитектура, тесты, README, умение защитить компромиссы.
Текстом работает, если кандидат даст репозиторий агенту.

### 9. Behavioral

Структура: 30–45 минут, вопросы «Расскажите о случае, когда…». Amazon требует ответ по STAR (Situation, Task, Action, Result) и связь с Leadership Principles [8].
Сигналы Tech Interview Handbook [2]: мотивация, проактивность, работа в неопределённости, упорство, разрешение конфликтов, эмпатия, рост, коммуникация. Hire-решение требует позитивных сигналов почти по всем восьми областям на ожидаемом уровне.
Текстом работает хорошо: STAR легко проверить по структуре.
Сложно: проверить правдивость истории и оценить невербальное поведение.

## Рекомендация для версии 1

Реалистичны четыре формата. Все они работают текстом и укладываются в Grade 0–3 и до двух Follow-up.

1. **Вопросы по темам подряд.** Базовый формат с минимальными входными данными. Даёт больше всего Attempt для Topic status.
2. **Разговор по резюме и опыту.** Использует Candidate profile и вакансию из Target. Это главный довод за локальный слой над агентом.
3. **Одна тема вглубь.** Нужна цепочка Question: каждый следующий вопрос продолжает предыдущий. Follow-up остаются уточнениями.
4. **System design (классический и LLM).** Ограничение: текстовое описание схемы. Grade ставят по этапам, а не по одному ответу.

Behavioral можно добавить как вариант формата 2 почти без затрат. Live coding и take-home отложить до алгоритмических задач из границ версии 1. Логические задачи не делать.

### Как описать формат шаблоном

Шаблон Interview format может содержать такие поля:

| Поле | Пример для «Одна тема вглубь» |
|---|---|
| `inputs` | Target (роль, уровень); Topic; резюме не нужно |
| `arc` | разогрев → определение → механизм → граничные случаи → применение → предел знаний |
| `question_kinds` | открытый вопрос; quiz с проверкой кодом; «что будет, если…» |
| `follow_up_policy` | до двух уточнений; переход вглубь создаёт новую Question |
| `stop_rule` | две подряд Grade ≤ 1 или конец лимита времени |
| `grading_criteria` | 0 — нет ответа; 1 — термин без механизма; 2 — механизм без границ; 3 — механизм, границы и компромиссы |
| `debrief_focus` | уровень, на котором ответ сломался; следующая тема |

Для system design `arc` повторяет этапы Авито: требования, схема, погружение, риски. `grading_criteria` тогда повторяют сигналы из раздела 4. Для разговора по резюме `inputs` обязательно включают резюме, а критерии оценивают личный вклад и цифры.

# Interview Sensei

Локальная подготовка к техническим собеседованиям с агентом, которым вы уже пользуетесь.

Статус: начало проекта. Есть скелет приложения: служебный чат с агентом, без предметных функций.

## Идея

Вы открываете приложение и проходите мок-собеседование. Его ведёт ваш агент: Claude Code, Codex или другой.
Приложение хранит вопросы, ответы и прогресс по темам. Новая сессия продолжает подготовку, а не начинает с нуля.

Первая версия открыта и работает локально. Свой LLM-клиент, ключи и аккаунты ей не нужны.
Границы версии описаны в [docs/requirements.ru.md](docs/requirements.ru.md).

## Запуск

Запустите приложение одной командой:

```bash
npx interview-sensei
```

Пакет `interview-sensei` появится в npm после первой публикации. До неё запускайте приложение [из клона репозитория](#запуск-из-клона-репозитория).

Команда скачивает пакет, запускает сервер на `http://127.0.0.1:4310/` и открывает этот адрес в браузере.
Приложение открывается на холсте последней цели. Без целей страница предлагает открыть демо-цель.
Ссылка «Проверка агента» в верхней панели открывает чат с агентом.
Сервер работает, пока вы его не остановите. Остановите его клавишами `Ctrl+C`.

### Что нужно заранее

- Node 22.15 или новее. Вместе с Node ставится `npx`.
- Вход в своего агента хотя бы одного вида:
  - Claude Code: войдите в `claude`, как обычно. Приложение использует ваш вход.
  - Codex: выполните `codex login`.
  - OpenCode: установите OpenCode, чтобы команда `opencode` была в `PATH`, и войдите в него.

Свой LLM-клиент и ключи приложению не нужны: оно работает через вашего агента.

### Флаги

| Флаг | Что делает |
| --- | --- |
| `--port <порт>` | Задаёт порт. Если он занят, приложение завершается с сообщением. |
| `--data-dir <каталог>` | Задаёт каталог данных вместо `~/.interview-sensei`. |
| `--no-browser` | Не открывает браузер. |
| `--help` | Показывает справку. |

Без `--port` приложение берёт порт 4310. Если он занят, приложение берёт следующий свободный порт до 4319 и печатает адрес.
Переменные окружения тоже работают: `SERVER_PORT` задаёт порт, `INTERVIEW_SENSEI_DATA_DIR` задаёт каталог данных, `INTERVIEW_SENSEI_NO_BROWSER=1` отключает браузер. Флаг важнее переменной.

### Запуск из клона репозитория

Этот способ нужен для разработки. Ему нужны Node 24 и pnpm 12:

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

`pnpm build` собирает веб-приложение, кладёт рядом копию `skills/` и собирает npm-пакет в `apps/server/dist/package`.
`pnpm start` выполняет ту же команду `interview-sensei` из исходников и принимает те же флаги: `pnpm start --no-browser`.
`pnpm dev` запускает сервер и Vite с горячей перезагрузкой, а браузер не открывает. Сервер `pnpm dev` слушает только порт 4310 или порт из `SERVER_PORT`.

## Как идёт разработка

Проект разрабатывают агенты по процессу из [agent-harness](https://github.com/KirillSachkov/agent-harness):

1. Обсуждение и issue. Полная spec нужна по сложности задачи.
2. Владелец явно запускает `implement` или `implement-spec`.
3. Работа в отдельном worktree, проверки, независимое Standards и Spec review.
4. `ship` готовит PR и ждёт CI. Владелец принимает результат и разрешает merge.

[Карта процесса](docs/process.ru.md) описывает шаги подробно. Правила агента находятся в [AGENTS.md](AGENTS.md).

## Данные

Приложение хранит все данные в каталоге `~/.interview-sensei`. Другой каталог задаёт флаг `--data-dir` или переменная окружения `INTERVIEW_SENSEI_DATA_DIR`.
Сервер создаёт каталог при первом запуске. В нём лежат база `database`, её копия `database.dump.tar.gz` и lock-файл `server.lock` работающего сервера.
Сервер обновляет копию базы раз в пять минут и при остановке.
Один каталог использует только один запущенный сервер. Второй сервер на том же каталоге завершается с сообщением об ошибке.

# Версия 1 расширяет готового агента через MCP и skills

Версия 1 не содержит собственного агентного цикла и вызовов provider. Собеседование ведёт агент пользователя: Claude Code, Codex, OpenCode и другие.
Детерминированную часть выполняет наш код: формат данных, запись попыток, расчёт прогресса. Агент получает доступ к ней через MCP-сервер.
Суждения агента задают skills: как вести сессию, как оценивать ответ, как исследовать тему и разбирать источники. Собственные инструменты агента, например веб-поиск и shell, остаются его инструментами.
Кандидат общается с агентом только в нашем UI. Сервер приложения запускает агента через ACP и передаёт ему наш MCP-сервер в `session/new`. Терминальный режим не поддерживается: в нём нет canvas, Side thread и управления каждым prompt.

## Considered Options

- Собственный агент с API-ключами: даёт контроль над поведением и контекстом, но требует ключей и относится к версии 2.
- Только ACP-чат без MCP: тогда данные зависят от того, как агент запишет ответ. Схемы инструментов это исключают.
- Только CLI вместо MCP: работает в любом агенте, но не даёт схем инструментов.
- Агент в терминале вызывает наш MCP, а canvas показывает вопросы: проще и явно разрешён подпиской Claude, но разговор остаётся в терминале, а Side thread неудобен.
- Нативные интерфейсы каждого агента (Claude Agent SDK, `codex app-server`): больше возможностей, но отдельный код на каждого агента.

## Consequences

- Правило «без подсказок до ответа» — просьба к агенту, а не гарантия кода.
- Качество оценки зависит от модели пользователя.
- Claude подключается через `claude-agent-acp`, то есть через Agent SDK. На 2026-11-08 такое использование подписки списывается из отдельных кредитов Agent SDK, а правила Anthropic для него неоднозначны. Пользователь должен знать это до запуска.

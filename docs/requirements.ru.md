# Согласованные границы

Interview Sensei помогает готовиться к техническим собеседованиям с агентом, которым человек уже пользуется.
Документ разделяет открытую первую версию и закрытую вторую.

## Версия 1: open source, локально

Версия 1 работает как локальный слой над существующим агентом, например Claude Code или Codex.
Собеседование ведёт агент пользователя. Приложение хранит данные и показывает прогресс.
Кандидат общается с агентом только в интерфейсе приложения. Приложение подключает агента через ACP.
Каждый агент из списка поддерживаемых работает полноценно: Claude Code, Codex и OpenCode. Новый агент попадает в список только с той же полнотой поддержки.
Известное ограничение: OpenCode 2.x работает в приложении только со входом по API-ключу. Вход по подписке (OAuth) приложение агенту не передаёт ([#69](https://github.com/KirillSachkov/interview-sensei/issues/69)).

Версия 1 состоит из вертикальных срезов. [#11](https://github.com/KirillSachkov/interview-sensei/issues/11) задаёт их порядок и зависимости.
Решения по интерфейсу рабочие: их задаёт [итог #18](https://github.com/KirillSachkov/interview-sensei/issues/18#issuecomment-6734007077), а spec срезов уточняют.

| Срез | Что получает кандидат |
| --- | --- |
| 0. Скелет ([#17](https://github.com/KirillSachkov/interview-sensei/issues/17)) | Кандидат пишет агенту и видит ответ на экране «Проверка агента». |
| Общая модель, до срезов 1–3 | Тикет вводит Target, Section, Topic и Question. Демо-набор вопросов даёт данные срезу 3. |
| 1. Настройка направления | «Новая цель» создаёт черновик цели, и агент настройки начинает онбординг. Кандидат прикрепляет материалы в чате настройки. Агент собирает Interview plan, темы и первые вопросы в черновике изменений, а кандидат применяет его разом. Кандидат выбирает агента цели, архивирует и удаляет цель. |
| 2. Inbox | Кандидат запускает разбор материалов кнопкой. Сервер извлекает из них текст. Агент разбора в фоне добавляет вопросы с опорным ответом из материала и пишет Inbox report. |
| 3. Мок-собеседование | Кандидат проходит Mock interview с лимитом времени или без него. Он отвечает свободно или в квизе и получает Grade 0–3 и Debrief. Он оспаривает Grade и оценивает вопросы. Приложение показывает Topic status и готовность. |
| 4. Side thread | Кандидат открывает Side thread у вопроса, сообщения агента или разбора и получает объяснение. |
| 5. Пауза и продолжение | Кандидат ставит Mock interview на паузу и продолжает его с тем же агентом. Если агент недоступен, кандидат начинает новый Mock interview с итогом прошлого. |

Правила материалов в Inbox:

- Inbox принимает файлы любого типа до 100 МБ, включая архивы.
- Текст извлекает сервер, а не агент: из PDF, DOCX, TXT, MD, субтитров и веб-страниц. Агент разбора читает текст частями.
- Если сервер не извлёк текст, Source получает статус «ошибка» с причиной. Архивы сервер не распаковывает: такой Source тоже получает «ошибку».
- У цели одновременно идёт не больше одного разбора.
- Видео кандидат добавляет файлом или ссылкой. Сервер превращает его в текст до агента разбора. Если у ссылки есть ручные субтитры, сервер берёт их.
- Иначе сервер распознаёт речь локально. Перед первым распознаванием приложение предлагает скачать компоненты распознавания в свой каталог данных. Загрузка начинается только после согласия кандидата.
- Кандидат выбирает модель: GigaAM v3 для русской речи, Parakeet TDT 0.6B v3 для 25 европейских языков или обе.
- Распознавание одинаково работает на macOS, Linux и Windows. Решение «вариант A» и уточнения V1–V7: [#36](https://github.com/KirillSachkov/interview-sensei/issues/36); spec: [#74](https://github.com/KirillSachkov/interview-sensei/issues/74); замеры: [исследование](research/video-transcription.ru.md).
- Кандидат может вместо распознавания приложить свой транскрипт.

Правила банка вопросов ([#63](https://github.com/KirillSachkov/interview-sensei/issues/63)):

- У вопроса есть опорный ответ: 3–5 ключевых пунктов, короткий образец ответа и метка источника. Это подсказка для оценки, а не истина: агент мока может не согласиться с опорным ответом и объясняет почему.
- Разбор Inbox пишет опорный ответ только из самого материала ([#47](https://github.com/KirillSachkov/interview-sensei/issues/47)). Если ответа в материале нет, вопрос остаётся без опорного ответа.
- «Наполнение ответов» ищет опорные ответы в интернете в фоне ([#70](https://github.com/KirillSachkov/interview-sensei/issues/70)). Кандидат запускает его кнопкой в зоне «Цель». Перед запуском приложение показывает число вопросов без ответа и оценку числа поисков и предупреждает, что наполнение тратит лимиты подписки агента. Переключатель «Наполнять в фоне» по умолчанию выключен.
- У темы есть важность: высокая, обычная или низкая ([#65](https://github.com/KirillSachkov/interview-sensei/issues/65)). Агент настройки берёт её из вакансий, кандидат меняет её через чат настройки.
- Мок оценивает ответ по опорному ответу и отбирает вопросы с учётом важности темы ([#64](https://github.com/KirillSachkov/interview-sensei/issues/64)).

Вне версии 1:

- Алгоритмические задачи, live coding, take-home и выполнение кода.
- Логические задачи.
- Голосовой ввод.
- Терминальный режим без интерфейса приложения.
- Тёмная тема. Её добавит отдельный тикет; интерфейс сразу берёт цвета из CSS-токенов.
- Перенос вопросов и памяти между целями.
- Автоматическая проверка сессий и оценок на эталонном наборе ([#66](https://github.com/KirillSachkov/interview-sensei/issues/66)). Пока владелец проверяет их вручную.

Границы:

- Нет собственного LLM-клиента, ключей provider API и серверных аккаунтов.
- Данные остаются на устройстве пользователя.
- Проект не учитывает юридические риски источников. Локальная база может содержать любые материалы, которые добавил пользователь или нашёл агент.
- Открытый репозиторий не поставляет сторонний контент. В нём есть только небольшой демо-набор вопросов, который написали мы или агент.

## Версия 2: закрытая, отдельный репозиторий

Версия 2 строит собственного агента: вызовы provider, инструменты, поиск, память и организацию вокруг агента.
Она добавляет аккаунты, работу нескольких пользователей и доводится до production.
Версия 2 развивается в отдельном закрытом репозитории. Этот репозиторий может только ссылаться на неё.

## Процесс

Каждая реализация начинается с ограниченной issue; полная spec нужна по сложности.
Владелец явно запускает реализацию. Независимые реализации идут в отдельных worktree.
Standards и Spec reviewers работают в свежем контексте. `ship` передаёт владельцу проверенный PR.
Агентские инструкции пишутся на английском. Всё, что читает человек, пишется на русском: PR, issues, spec, отчёты и документы.
